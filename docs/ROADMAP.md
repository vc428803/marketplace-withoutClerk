# 開發路線圖（ROADMAP）

## 目標

整合既有 Marketplace（React + Golang + PostgreSQL）
與 NEXELYTH（Unity C#），建立共用玩家身分與跨平台物品管理。

## 開發階段

| 階段 | 開發項目 | 狀態 |
|---|---|---|
| 01 | 檢查既有 Golang 登入與 JWT 機制 | 待驗證 |
| 02 | Unity 登入與共用 User ID | 規劃中 |
| 03 | 遊戲背包與物品實體模型 | 規劃中 |
| 04 | VR 背包移入交易暫存區 | 規劃中 |
| 05 | Marketplace 查看待上架物品 | 規劃中 |
| 06 | 商品刊登與交易流程整合 | 規劃中 |
| 07 | 買家待領取區與背包領取 | 規劃中 |
| 08 | WebSocket 物品變更通知 | 後續規劃 |

## MVP 驗收條件

- [ ] 同一帳號可以登入 Marketplace 與 NEXELYTH
- [ ] 後端能驗證玩家身分與 User ID
- [ ] 玩家可在 VR 將物品移入交易暫存區
- [ ] 移入交易暫存區後，物品不可繼續使用
- [ ] Marketplace 可查詢玩家自己的待上架物品
- [ ] 物品交易狀態與所有權由後端管理
- [ ] 交易完成後，買家可在 VR 領取物品
- [ ] 同步或重新查詢後，兩個平台顯示一致狀態

## 原則

優先重用既有 Golang API。
暫不為了技術棧展示而額外建立 Java 或 C# Game API。
待遊戲業務複雜度提高，再評估服務拆分。
